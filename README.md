# وكالة الأنباء التنسيقية — CNA (Coordination News Agency)

موقع إخباري كامل مبني بـ **Next.js 14 + TypeScript** (App Router)، جاهز للنشر على **Vercel**،
بقاعدة بيانات **Postgres** وتخزين صور عبر **Cloudinary**، وبريد عبر **Google Workspace SMTP**.

> ملاحظة حول الفريمورك: تم بناء الموقع بالكامل بـ React (عبر Next.js) بدل خلط React/Vue/Angular،
> لأن دمج ثلاث فريمورك في مشروع واحد على Vercel غير عملي تقنياً (انظر شرح القرار في المحادثة).
> التنظيم المطلوب (رئيسية / مقال / لوحة تحكم) محقق عبر فصل المسارات (`/`, `/article/[slug]`, `/admin`)
> داخل نفس المشروع — بنفس مستوى الفصل البرمجي بدون تعقيد النشر.

## ✅ ما تم بناؤه وهو يعمل فعلياً

- **الهيكلة الكاملة**: Next.js + TypeScript + Prisma schema يغطي كل الأنظمة المطلوبة
- **نظام التصميم الديناميكي**: يُطبَّق بالغصب على كل الموقع فوراً من `/admin/settings`
- **بوابة الدخول الموحدة الكاملة**: تسجيل → تفعيل إيميل → موافقة عمادة القبول (`/admin/users`) → دخول
- **الصفحة الرئيسية، صفحة المقال، لوحة التحكم الرئيسية بإحصائيات حية**
- **محرر المقالات (CMS)**: `/admin/articles` — Quill محلي بالكامل، رفع صور Cloudinary، تدفق مراجعة كامل (محرر → مراجع)
- **الخبر العاجل**: `/admin/breaking-news` — شريط/شاشة منبثقة/الاثنان، تفعيل وإيقاف
- **الاستطلاعات والتصويت**: `/admin/polls` (إنشاء + نتائج حية) و `/polls` (تصويت لمرة واحدة لكل مستخدم مسجل)
- **خريطة الانتخابات الأمريكية**: `/admin/elections` (تحديث كل ولاية حياً) و `/elections` (خريطة تفاعلية بالألوان + مجموع الأصوات الإلكترونية)
- **البث المباشر (LIVE)**: `/admin/live` و `/live` — تضمين يوتيوب
- **الجريدة اليومية**: `/admin/newspaper` (بناء آلي بحد أدنى 12 صفحة، صفحة لكل قسم) و `/newspaper` (متصفح كلاسيكي) + **تصدير PDF حقيقي**
- **الأخبار العالمية**: `/admin/world-news` — استعراض واستيراد من NewsAPI.org بقالب الموقع
- **أداة سحب المقالات الخارجية**: `/admin/scraper` — تستخرج العنوان والوصف والمحتوى والصورة والمؤلف والتاريخ من أي رابط وتستوردها بقالب CNA
- **إدارة الأقسام**: `/admin/departments`
- **نظام الأدوار السبعة الكامل مع تدفقات المراجعة والموافقة** (تفصيل كامل بالأسفل)
- **Seed script**: حساب "رئيس الوكالة" الأول + الأقسام الافتراضية

## 👥 نظام الأدوار السبعة

كل دور له صفحاته وصلاحياته الخاصة، مفروضة من السيرفر (API) وليس فقط مخفية بالواجهة:

| الدور | يقدر يسوي |
|---|---|
| **زائر** | تصفح + تصويت فقط |
| **محرر** | ينشئ/يعدّل مقالات — كل تعديل يروح "بانتظار المراجعة"، ما ينشر لحاله |
| **مراجع** | يوافق أو يرفض مقالات المحررين فقط (`/admin/review`) — لا يقدر يحرر مباشرة إلا يطلب صلاحية من المدير (زر بنفس الصفحة) |
| **مبرمج** | يقترح تعديل التصميم (`/admin/settings`) — يروح لصف انتظار المدير، ما يُطبَّق إلا بموافقته |
| **رئيس التحرير** | ينشر ويحذف مباشرة بدون مراجعة، ويتحكم بصلاحية كل محرر (`/admin/editors`) |
| **عمادة القبول** | قبول/رفض طلبات الحسابات فقط (`/admin/users`) — لا صلاحية أخرى إطلاقاً |
| **رئيس الوكالة (المدير)** | كل شيء: يعيّن أي دور لأي شخص (`/admin/roles`)، يوافق على التصميم (`/admin/design-review`)، وينشر/يطبّق مباشرة أيضاً |

الحساب الأول (راجع قسم "حساب الأدمن الأول" بالأسفل) يُنشأ بدور **رئيس الوكالة** تلقائياً — منه تعيّن البقية من `/admin/roles`.

## 🎨 تحسين المظهر

- خطوط Cairo وAmiri مستضافة محلياً بالكامل (بدون أي اتصال خارجي وقت التشغيل)
- هوية بصرية جديدة بطابع "وكالة أنباء رسمية": كحلي غامق + ذهبي نحاسي (بدل الأزرق العام السابق)، مع خط Amiri للعناوين تحديداً
- هيدر بطراز "الترويسة الرسمية" (masthead) مع شريط تاريخ وختم دائري افتراضي قبل رفع الشعار
- شريط الخبر العاجل بلون أحمر ثابت دائماً (إشارة استعجال وظيفية لا تتغير مع الثيم) بدل تتبع لون التمييز
- بطاقات الأخبار بأسلوب "الدايتلاين" (تاريخ مختصر بجانب القسم) المستخدم بوكالات الأنباء الحقيقية

## ⚡ تحسين السرعة

كانت كل صفحة (`force-dynamic`) تعيد الاستعلام من قاعدة البيانات من الصفر مع كل زيارة. الآن:
- الصفحة الرئيسية، المقال، الجريدة، الانتخابات، البث المباشر تستخدم تخزين مؤقت (ISR) بدل إعادة التحميل الكامل
- أي نشر/تعديل من لوحة التحكم يفرّغ التخزين المؤقت فوراً (`revalidatePath`) فتظهر التغييرات مباشرة رغم التخزين المؤقت — سرعة وحداثة معاً
- صفحة الاستطلاعات بقيت فورية (`force-dynamic`) عمداً لأنها تعرض حالة تصويتك الشخصية

## 🚧 يحتاج ضبطاً إضافياً بعد النشر (وليس بناءً من الصفر)

- ضبط مفتاح `NEWSAPI_KEY` وحدود الاستخدام المجانية (100 طلب/يوم في الخطة المجانية)
- الاستيراد الآلي المجدوَل (cron) للأخبار العالمية والخبر العاجل الآلي — حالياً الاستيراد يدوي بالضغط على زر
- محرك سحب المقالات مبني على استخراج عام (`<article>` أو أطول فقرات) وقد يحتاج تخصيصاً لمواقع معينة صعبة البنية
- التحسين البصري ركّز على الصفحات اللي يشوفها الزوار (الرئيسية، الهيدر، بطاقات الأخبار) ولوحة التحكم الرئيسية. نماذج الإدارة الداخلية (مثل نماذج إضافة استطلاع أو خبر عاجل) شغّالة بالكامل لكن ما زالت بتصميم بسيط وظيفي — تحتاج جولة تحسين بصري منفصلة لو تبيها

## 🛠️ الإعداد المحلي (اختياري — غير مطلوب للنشر على Vercel)

القسم التالي فقط لمن يريد تجربة المشروع على جهازه الشخصي قبل النشر. **إذا كنت سترفع مباشرة لـ Vercel فلا حاجة لأي من هذه الأوامر إطلاقاً** — راجع قسم النشر أدناه.

```bash
npm install
cp .env.example .env      # عبّي القيم: Postgres, Cloudinary, Google SMTP
npx prisma db push
npm run db:seed           # ينشئ حساب "رئيس الوكالة" الأول (راجع الطرفية للبيانات)
npm run dev
```

## 🚀 النشر على Vercel — بدون أي أوامر (Zero Commands)

تم ضبط المشروع بحيث لا تحتاج تكتب أي أمر إطلاقاً. عند رفعه لـ Vercel:

1. ارفع مجلد المشروع إلى مستودع GitHub (رفع ملفات عادي، ليس أمر طرفية).
2. من Vercel: **New Project** → اختر المستودع → Vercel يكتشف Next.js تلقائياً.
3. في شاشة **Environment Variables** (نقر وتعبئة، وليس أمر) أضف القيم الموجودة في `.env.example`:
   - `DATABASE_URL` (من Vercel Postgres أو Neon أو Supabase — تُنشأ من واجهة الويب الخاصة بهم)
   - `NEXTAUTH_URL` (رابط موقعك على Vercel) و `NEXTAUTH_SECRET` (أي نص عشوائي طويل)
   - بيانات Cloudinary الثلاثة
   - بيانات SMTP الخاصة بـ Google Workspace
   - `NEWSAPI_KEY`
4. اضغط **Deploy**.

من هنا يتولى Vercel كل شيء تلقائياً أثناء البناء:
- `npm install` يُشغّل `prisma generate` تلقائياً (عبر `postinstall`)
- خطوة البناء `npm run build` تُشغّل: توليد Prisma Client → مزامنة قاعدة البيانات (`prisma db push`) → **إنشاء حساب أدمن أولي تلقائياً + الأقسام الافتراضية** (`prisma/seed.ts`، آمن يتكرر كل نشر بدون تكرار الحساب) → بناء Next.js

### 🔑 حساب الأدمن الأول

إذا لم تضِف `SEED_ADMIN_EMAIL` و `SEED_ADMIN_PASSWORD` في متغيرات البيئة، يُنشأ حساب افتراضي تلقائياً:

- **البريد**: `admin@cna.local`
- **كلمة المرور**: `ChangeMe123!`

**غيّرها فوراً بعد أول تسجيل دخول**، أو الأفضل: أضف `SEED_ADMIN_EMAIL` و `SEED_ADMIN_PASSWORD` بقيم خاصة بك في Environment Variables **قبل** أول نشر، بحيث يُنشأ الحساب بها مباشرة.

بعد الدخول بحساب الأدمن، تقدر تدخل `/admin` للوصول للوحة التحكم الكاملة.

> ⚠️ **تنبيه مهم**: بما أن قاعدة البيانات تُزامَن تلقائياً بـ `prisma db push --accept-data-loss` في كل عملية نشر (لتفادي أي أوامر يدوية)، فإن أي تعديل مستقبلي على `schema.prisma` يُطبَّق فوراً عند النشر التالي — بما في ذلك حذف عمود إن كان يحتوي بيانات لن تعود. هذا مناسب تماماً لمرحلة الإطلاق الحالية. لاحقاً، عندما تصبح قاعدة البيانات فيها محتوى حقيقي مهم، ينصح بالتحول لنظام ترحيل (migrations) مُراجَع بدل المزامنة التلقائية.

## ✅ فحص الجودة (Quill والـ TypeScript)

تم رفع Quill إلى الإصدار **2.0.3** (يشحن أنواع TypeScript الخاصة به مباشرة، بلا حزمة `@types` منفصلة قد تتعارض)، وتم تشغيل فحص TypeScript الصارم (`strict: true`) على كامل المشروع وإصلاح كل خطأ ظهر (كانت أخطاء `implicit any` في استدعاءات `.map`/`.filter`، وتم إصلاحها جميعاً بأنواع صريحة). لا توجد أي أخطاء متبقية باستثناء رسالتين متوقعتين ومصدرهما فقط أن بيئة الفحص هنا لا تصل لخوادم Prisma لتوليد الحزمة الحقيقية؛ تختفيان تلقائياً بمجرد أن يُشغّل Vercel `prisma generate` بنفسه (وهو ما يحدث تلقائياً كما هو موضح أعلاه).
